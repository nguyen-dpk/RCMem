% --- 1. The general problem of the field
Embodied agents are increasingly expected to work over long horizons: a
household robot may receive one request after another in the same home, each
naming several objects, and cannot afford to search the house from scratch
every time. Memory has therefore become a central component of recent
navigation agents built on vision-language models (VLMs). Reusing memory,
however, brings a decision that a memoryless agent never faces. Whenever a new
goal arrives, the agent must judge whether the goal is already in its memory:
if it is, the agent should \emph{commit} and travel to the remembered object;
if it is not, it should \emph{explore}. The two errors are not symmetric. A
needless exploration costs only steps, whereas a wrong commitment costs a
wasted trip and often the goal itself. Every memory-based agent makes this
decision, whatever form its memory takes, and in multi-goal tasks it makes it
at nearly every step (\cref{fig:teaser}).

% --- 2. Previous work, and why it falls short
Work on memory for embodied search has mostly improved \emph{what} is remembered
and \emph{how} it is found, from multi-view snapshots~\cite{3dmem} and RL-trained
retrieval~\cite{lmee} to compressed views held in the model's
context~\cite{astranav}, room-level graphs~\cite{stegnav,evomemnav} and 3D
Gaussian maps~\cite{gsmem,lagmemo}. These designs make memory richer and easier
to search, but none tells the agent when its memory is still incomplete. Where the question of \emph{when} to trust
memory is addressed, it is mostly handled after the agent has travelled: the
target is verified on arrival~\cite{stegnav,evomemnav}, checked against the
expected room~\cite{contextnav}, or re-rendered and checked
again~\cite{3dgsnav}. The closest exception is EvoMemNav~\cite{evomemnav},
where a low-confidence anchor choice sends the agent back to exploring.
Checking after the trip can only reject a choice that has already been paid
for, and when the goal has not been seen yet there is nothing right to fall
back on: a rejected agent simply commits to the next remembered candidate.

% --- 3. Thesis
% \paragraph{The bottleneck is the commitment.}
We argue that memory-based agents fail less at remembering than at deciding
whether what they remember is enough. To test this, we take a strong
retrieval-based agent, MemoryExplorer~\cite{lmee}, on LMEE-Bench~\cite{lmee}
in HM3D-Sem scenes~\cite{hm3dsem}, and label every commitment with simulator
ground truth: regions, instances and their visibility. Retrieval is rarely the
problem: very few navigation failures are retrieval misses. Instead, more than
half are commitments to the wrong remembered object, most of them made before
the goal had been seen at all (\cref{tab:diagnosis}a). Until the goal's region
has been observed, the agent commits as often when the goal is absent from
memory as when it is present: it cannot tell that its memory is incomplete
(\cref{tab:diagnosis}b).

% --- 4. Challenges
% \paragraph{Challenges.}
Making this decision well raises three challenges.
\begin{enumerate*}[label=(\roman*)]
  \item \emph{Representing absence.} To know that the goal is not yet in
    memory, the agent must see what it has \emph{not} observed, but retrieved
    views and frame streams record only what it has.
  \item \emph{Scoping by region instance.} The decision must be tied to a
    specific place. Room names are not enough: homes contain several rooms of
    the same type, and many regions carry no label. Nor is more memory the
    answer; holding the model fixed, keeping the whole history in its context
    shows it every distractor at once and lowers the success
    rate (SR) below the retrieved bank.
  \item \emph{Learning to abstain.} Memory always offers a best match, even
    when the goal is not there. To set it aside, the agent must learn from
    cases in which the goal is absent and exploring is the right answer, and a
    wrong commitment must cost it more than a needless exploration.
\end{enumerate*}

% --- 5. What we propose
% \paragraph{\ours.}
We propose \ours{} (Region-scoped Context Memory), a VLM whose context is its
memory, organised by region, with one design element per challenge. Observations
are pruned by 3D novelty and assigned to regions segmented from the free-space
map~\cite{bormann2016room}. Each region enters the context as one panorama
rendered from the point that sees most of it, and pixels that nothing has
observed stay grey, so the model sees both what a region contains and what it
has yet to show~(i). Regions are instances without labels: whether a region is
the bedroom a subtask refers to is read from its pixels. The agent commits in
two steps before it moves: from the panoramas and one view per frontier, it
chooses a region or to explore; then, from that region's frames alone, it
selects the goal or declines~(ii).
% If the frozen zero-shot config (RPcu) stays the main one, add its room
% close-ups here, e.g. ``with a few close-up views of each region''.
We fine-tune \ours{} on streams in which the goal is often absent, then train
the decision with an Expected Commitment Reward (ECR): where
GRPO~\cite{deepseekmath} samples rollouts, ECR grades every option from ground
truth, charging a misleading commitment the most and rewarding exploration by
its progress toward the goal~(iii). Outside the model, \ours{} stores only the
pruned frames, their camera poses and the floor map, with no retrieval index.

% Dev reference (P3, subset, seed 77, zero-shot, Qwen3-VL-8B; not main results):
% F1 31.2, RCMem RP 34.6, RPcu 38.6 SR.
We evaluate on the full LMEE-Bench (166 tasks, three seeds) and on
GOAT-Bench~\cite{goatbench}. \ours{} runs on Qwen3-VL-8B~\cite{qwen3vl}; since
the strongest baseline uses Qwen2.5-VL-7B, we report the backbone's gain
separately with same-backbone controls. \ours{} improves SR by \tbd{+X} over
the strongest baseline, \tbd{+Y} of which comes from the method rather than
the backbone, and substantially reduces premature commitments.

\noindent In summary, we make three contributions:
\begin{enumerate}
  \setlength{\itemsep}{1pt}
  \item \textbf{\ours.} A context memory with one panorama per region that
    shows unobserved space, and a two-step commitment, first a region or
    ``explore'', then a target within that region, made before the agent moves.
  \item \textbf{Expected Commitment Reward (ECR).} Training on absent-goal
    streams with a reward that grades every option, so a misleading commitment
    costs the most and exploring earns by its progress.
  \item \textbf{Evaluation.} We conduct extensive experiments on LMEE-Bench and
    GOAT-Bench, with repeated runs and an explicit noise band, a QA metric
    corrected for the answer-letter prior, and same-backbone controls that
    separate the backbone's gain from the method's.
\end{enumerate}
