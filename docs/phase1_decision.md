## E3: commit-rate diagnostic (all E0 runs, per navigation decision)

A decision *commits* when the agent picks a memory object instead of a frontier. *Goal in memory*: a stored memory view shows a goal instance (≥ 0.1% of the frame, semantic sensor). *Goal region observed*: some stored view up to that decision is dominated by the goal's HM3D region.

| Condition | Decisions | Commit rate % |
|---|---|---|
| goal in memory | 977 | 35.7 |
| goal not in memory | 1459 | 21.3 |
| goal region observed / goal in memory | 864 | 37.2 |
| goal region observed / goal not in memory | 183 | 13.7 |
| goal region not observed / goal in memory | 113 | 24.8 |
| goal region not observed / goal not in memory | 1276 | 22.4 |

The commit rate is 14.4 points higher when the goal is in memory, which is above the 10-point threshold, so **C2 does not hold as stated**. The agent does discriminate once the goal's room has been seen (37.2% vs 13.7%), but not before: with the goal's room unobserved it commits at 24.8% vs 22.4%. It also still commits in 21.3% of decisions where the goal is absent from memory.

## Consequences for the plan

- **GO**: continue to P3 as planned. The oracle region gate beats both simple fixes by more than the rule requires, so C5 stands as written.
- **Reword C2** before writing: the agent cannot tell that the goal is absent *while the goal's room is unobserved*; once the room is seen it commits less when the goal is absent. Report the E3 table split by region observation, not the pooled rates.
- **QA**: the region gate on QA lowers accuracy; RCMem's QA ranking (P3) needs its own check rather than reusing the E1 rule.

## Notes and caveats

- E1 and E5 use ground truth (HM3D regions/instances): oracles only, as DEV_PLAN.md allows. E2 and E4 use the task-config room name.
- E4's verifier is one zero-shot Qwen2.5-VL call with the subtask text, the room and (image goals) the goal image; a stronger verifier could do better, so E4 is a lower bound for verify-on-arrival.
- The baseline still has the NaN start-orientation bug (fixed in P2), identically in every run here.
- On 2026-10-19 GPU 3 briefly reported no CUDA device; four half-runs failed at start-up, were re-queued and completed (`analysis/runs/p1_queue.log`). Runs resume per episode, so no partial episode is counted.
