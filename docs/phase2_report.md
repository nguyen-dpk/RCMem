## 1. Start-orientation fix (3 seeds each, 58-task subset)

## 2. E1 (oracle region gate) and E1b (room-type gate) on the fixed baseline

E1b keeps every region whose room type matches the subtask's room. Room types: task-config labels where available, otherwise a vote over the region's ground-truth objects (`analysis/room_types.py`); regions of unknown type are never hidden.
 Of 489 regions, 181 have a config label, 162 are typed by the object vote (vote agrees with the config on 159/168 = 94.6% of labelled regions) and 146 stay unknown.

- **E1 fixed**: ΔSR +15.8, ΔSPL +8.7, Δpremature-commit -27.1, Δacc -0.7 vs the fixed E0 mean; 2 × std = 3.1 → beyond noise.
- **E1b fixed**: ΔSR +5.8, ΔSPL +3.4, Δpremature-commit -3.7, Δacc +0.2 vs the fixed E0 mean; 2 × std = 3.1 → beyond noise.
- E1b recovers 36% of E1's SR gain: this is the realistic ceiling for a memory that knows room types but not exact regions (G2 in DEV_PLAN.md asks zero-shot RCMem to close half of the E0→E1 gap).
- **Consequence for G2:** half of the E0→E1 gap is above the measured room-type ceiling. A memory that only knows room types is unlikely to pass G2 as written unless typing every region (below) closes most of the shortfall; RCMem should also bind each subtask to a specific region (which bedroom), e.g. through the instruction's room order and visit history. Re-check G2 against E1b before P3 starts.
- Where E1b's remaining wrong commitments land (3 runs, 302 commitments to a distractor or another-category object): region of unknown room type (never hidden) 114 (38%); another room of the same type 100 (33%); same region as the goal 74 (25%); room of a different type 8 (3%); chosen object not matched to a GT region 6 (2%).
- So E1b is a *lower bound* on a perfect room-type ceiling: 38% of its misses land in regions that no label covers, which a VLM-labelled memory would type. Another 33% are in a second room of the same type; only region-level binding (which bedroom) removes those. Commitments inside the goal's own region (25%) are wrong instances that no room gate can fix.

Rejection precision 411/432 = 95.1%, rejection recall 411/458 = 89.7%; it rejected the true goal in 21/61 = 34.4% of arrivals at the goal. 458 of 519 arrivals were at a wrong object, so the high rejection rate in Phase 1 was mostly correct: E4 stays near the baseline because the agent re-commits to other wrong objects, and because true goals are rejected.
