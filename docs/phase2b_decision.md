## Method notes

- F1/F2/F2b (`analysis/p2b_experiments.py`) wrap the instrumented LMEE run at runtime; LMEE code and the baseline result files are unchanged. Retrieval (the CLIP knowledge base and its query call) is bypassed: the prompt holds the pruned frames in viewing order. Each frame shows the detector's boxes, numbered; the answer `Frame f, Object o` becomes the same single-object target the baseline navigates to. QA answers with `Frame f` and a letter, as the baseline does with memories.
- Empty-context rule: a navigation decision with no frame in context (F2/F2b before the goal's region or room type has been seen) goes to the nearest frontier without a VLM call; with no frontier left the subtask ends, as in the baseline. QA decisions fall back to all frames instead.
- A decision whose prompt does not fit the GPU (CUDA out of memory, 24 GB card shared with SAM/YOLO) drops the oldest 10% of its frames and is retried, the same rule as the 32k-token cap; such decisions are counted per run ("Trimmed after GPU OOM").
- F2 keeps only frames whose ground-truth region (pixel-weighted majority of visible instances) is the goal's region; F2b keeps frames whose region type matches (unknown types kept). Ground truth is used only for these oracles.
- The seed sets LMEE's scene order and the run's random draws; GPU inference is not bit-deterministic, so runs differ even at one seed.
